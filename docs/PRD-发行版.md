# applytracker 发行版 PRD

> 版本：v0.1（需求收敛稿）｜作者：许清楚（产品）｜日期：2026-10-07
> 目标：把作者自用的秋招投递看板，变成「同学在自己电脑上装一套就能用」的发行版。

---

## 0. 一句话定义

**每人本机一套，数据各自留在自己电脑里，互不可见。** 三栏功能（投递进度 / 邮箱通知 / 机会库）照旧；各人连自己的邮箱、各人装自己的浏览器扩展。作者那套依赖自己飞书账号的链路，在别人那一套里全部换成不等价的本地替代或直接砍掉。

需要新做的只有一件事：**让别人能连上自己的邮箱**（作者现在这步靠自己的 WorkBuddy 连接器凭据，别人拿不到）。

---

## 1. 问题陈述

**谁**：秋招/暑期实习的同学，同时投 30+ 家，普通用户（非开发者），手上只有一台自己的电脑。

**什么场景**：在官网点完「提交申请」，过两天邮箱来一封「请于 X 月 X 日前完成测评」。投了哪些家、哪家来消息了、哪家的 deadline 快到了——散在浏览器标签、邮箱、聊天记录里。

**现在怎么解决**：手抄 Excel，或者拿飞书/Notion 建一张表。三周之后表就不更新了（这是所有同类工具的公开经验：纪律一松就断更）。要么就得把邮箱授权给某个在线工具扫——很多人不愿意。

**为什么不行**：
- 手抄 → 投递那一刻不在电脑前/懒得切窗口，就漏记，事后完全不记得投过。
- 在线工具扫邮箱 → 要把邮箱交出去，隐私上过不去；且国内校招邮箱（QQ/163）很多工具根本不支持。
- 作者这套已经解决了上面两点（本地跑、扩展自动记、不上传），但只有作者能跑起来——因为它绑着作者自己的飞书账号和连接器凭据。

**发行版要填的洞**：把「作者专属的那几条链路」换成「任何一个同学都能自己配起来的那条链路」。

## 2. 目标用户

- **主要用户（决定成败）**：2027 届/2028 届在读或应届，年 19–25，2026 秋招正在海投。用 Windows 或 macOS 笔记本，日常上网、会装微信/QQ，**但没装过 Python、没用过命令行、不知道什么是「解压到目录」**。
- **次要用户**：已装过 Python 或写过一点代码的同学（能读 README、能改配置）。这批人几乎零门槛，不是设计约束，但他们的反馈最有用。
- **明确不服务的**：企业/团队协作、多设备同步、手机端。发行版就是「一台电脑 + 一个人 + 一份本地数据」。

设计基线（SaaS 数据密集风，来自行业知识库 `saas-b2b.md`）：极简、克制、表格为主、操作即时无「保存」步骤。看板本身已经是这个路子，发行版不改视觉语言。

## 3. 使用旅程（核心产物）

**从「同学收到你发的一个压缩包」到「真正用起来」。** 每一步都标出可能卡在哪、以及发行版要做的防呆。这份东西后面会拆成两份东西：① 给同学的《安装说明》；② 首次启动时的引导页。

| # | 同学要做的动作 | 卡在哪（非开发者视角） | 发行版要做的防呆 |
|---|----------------|------------------------|------------------|
| 0 | 从微信/网盘收到 `applytracker-发行版.zip`，下载、解压 | 不知道解压到哪；macOS 双击 zip 后文件散在「下载」里；Windows 解压出**双层目录**（zip 里套文件夹） | 压成**单层目录**；包里第一层就是文件，不许再套一层；附一张「先做这三步」的图 |
| 1 | **装 Python 3.9+** | 最大的坎。①压根不知道要装；②Windows 装的时候**忘了勾 Add to PATH**，后面双击全闪退；③macOS 系统自带的 `python3` 版本可能不对；④装完不知道成没成 | 提供**一键检测**入口（检测脚本/引导页第一屏就查 `python3 --version`）；把「必须勾 PATH」做成**带箭头的大字提示**贴在下载页；给出 macOS / Windows 两套下载直达链接 |
| 2 | 确认文件放对位置（解压出来的 `applytracker` 文件夹里能看到 `applytracker.py`） | 找不到 `applytracker.py`；文件被解压到桌面/下载夹的临时目录，之后被清掉 | 引导页显示「程序所在目录」；建议放到「文稿 / Documents」并说明原因（不会被系统清） |
| 3 | **起服务**：双击 `start.command`（macOS）/ `start.bat`（Windows） | ①macOS 双击 `.command` 被 Gatekeeper 拦：「无法打开，来自身份不明的开发者」；②Windows 双击闪退（多半是第 1 步没勾 PATH）；③**8788 端口被占**；④终端黑窗口被误关（以为可以关） | ①说明里写清 macOS 首次要「右键→打开」或到「隐私与安全性」放行；②`start.bat` 检测不到 Python 时**打印中文提示并 pause**，别一闪而过；③端口占用时自动换下一个端口并提示；④窗口里明确写「**这个窗口不要关**」 |
| 4 | 浏览器打开 `http://127.0.0.1:8788`（通常自动弹出） | 没自动弹；手打地址打错；以为要联网、以为要账号 | 引导页里直接给「点这里打开看板」的按钮；地址旁边注明「本机地址，不需要联网」 |
| 5 | **装浏览器扩展**：`chrome://extensions`（Edge 是 `edge://extensions`）→ 开「开发者模式」→「加载已解压的扩展程序」→ 选 `extension/` 目录 | ①找不到「开发者模式」开关在哪；②选目录时**选到了上一层**（选成 `applytracker` 而不是 `applytracker/extension`），报「清单文件缺失」；③Chrome 更新后扩展被停用；④若改过端口，忘了同步改扩展里的 `DEFAULT_PORT` | 说明里给**逐屏截图 + 高亮**；明确写「选的是 `extension` 这个文件夹本身」；端口自动发现（扩展连不上时提示当前服务端口，而不是要用户手改代码） |
| 6 | **连自己的邮箱**（首次）：开 IMAP → 拿授权码 → 填给程序 | ①找不到邮箱设置入口；②把「登录密码」当授权码填进去，一直登录失败；③授权码**只在弹窗出现一次**，关了就没了；④Gmail 还要先开「两步验证」；⑤163 叫「客户端授权密码」，名字不一样，同学以为不是同一样东西 | 给**逐家邮箱的图文引导**（QQ / 163 / Gmail / Outlook 各一页）；程序里做成**向导**（问邮箱地址 → 问授权码 → 当场试登录 → 提示成功/失败原因）；明确写「是授权码，不是登录密码」；**这一步允许跳过**（跳过 = 邮箱通知页给出「怎么回来配」的说明，不报错、不卡死） |
| 7 | 真投一次，试跑闭环 | ①投完没弹卡（站点提示语不认识）；②公司名认错；③服务没起，扩展记录失败 | 已有兜底：页面右侧「记一笔」标签 + 扩展图标「记录当前页」；公司名在看板上点着改 |
| 8 | （可选）知道数据在哪、怎么备份 | 不知道记录就是本地一个 CSV；重装/换电脑就把记录弄丢 | 引导页写明「你的记录在这里：`data/applications.csv`，用 Excel 能直接打开，复制走就是备份」 |
| 9 | （可选）看机会库 | 以为它是「每天更新的招聘库」，发现是发版那天的快照 | 机会库页顶明确写「数据截至 X 月 X 日，本地快照，不会自动更新」 |

**关键结论**：整条旅程里，真正会让同学放弃的是第 1、3、6 步（装 Python / 起服务 / 配邮箱）。第 5 步（装扩展）是烦但不至于放弃。第 4、7 步靠引导就能抹平。

## 4. MVP 范围 + 明确不做

### 4.1 作者飞书链路的三处处置（本 PRD 的核心取舍）

| 链路 | 现状 | 发行版怎么处置 | 原因 |
|------|------|----------------|------|
| **扩展写入端**（扩展 POST 到本机服务的 `/api/apply`，端口 8788） | 扩展把投递记进本地 `data/applications.csv` | **原样保留** | **这条根本不依赖飞书**，是纯本地链路（服务 `127.0.0.1` + 本地 CSV）。它是整个产品的核心，必须留。（注：没有单独的「8787 写入端」，写入就是同一个本地服务的 `POST /api/apply`，架构师会确认端口口径） |
| **飞书机会库同步**（`[opportunities] source = feishu`） | 后台线程每 6 小时去拉作者的飞书汇总表 | **砍掉同步，改用本地快照**：随包带一份 `data/opportunities.json`（约 9381 条），配置里设 `source = off`。页面照常读这个文件（`load_opportunities()` 不判 source）。 | 同学没有、也不该有作者那张飞书表。`source = off` 时看板**本来就能读本地缓存**，等于零改动能力已经具备。代价是数据冻结在发版日 —— 可接受，招聘信息本来也是公开招聘信息。 |
| **飞书通知表**（`[notices] source = feishu`） | 作者靠自己的定时任务+连接器把邮件写进飞书表，再看板读表 | **换成用户直连自己的邮箱**（见 4.2）。这是**唯一必须新做的部分**。 | 作者那条链路的凭据别人拿不到。邮箱通知这一栏要活，只能让每个人连自己的邮箱。 |
| **飞书投递进度同步**（`[applications] source = feishu`） | 看板和飞书表双向对齐状态 | **默认 `source = off`**，本地 CSV 就是唯一真相源。配置项保留、文档保留，给「自己也有飞书表」的高级用户用，但不进 MVP 引导流程。 | 同学没有这张表。留着这个开关不增加任何实现成本（代码已在），但默认关掉，避免误导。 |

### 4.2 「用户直连自己的邮箱」——MVP 的关键新增

现成资产：隔壁 `qqmail-job-tracker/qqmail2table.py` 已经是一个**零第三方依赖（只用 `imaplib`）+ 正则抽取 + 有交互式配置向导（问邮箱地址和授权码、当场试登录）**的本地脚本，产物正好是 `out/notifications.csv` —— 而 applytracker 的 `[notices] source = file` **本来就是读这个文件**。

**建议路径（供架构师决策，PM 不拍技术方案）**：把邮箱抓取能力并进发行版，新增 `[notices] source = imap`，用向导收集「邮箱地址 + IMAP 授权码」，直连用户自己的收件箱，复用 `qqmail2table` 的抽取规则（`TYPE_RULES` / 截止时间三层解析等）。三种 source 的定位：

- `imap`（发行版默认）——**连自己的邮箱**，向导配一次，之后自动抓；
- `file`——读现成 CSV（老用户/自定义流程）；
- `feishu`——作者自用保留，发行版不写进引导。

邮箱支持范围：**v1 先做 QQ 邮箱**（国内校招主力，授权码流程最短），host 做成可配置表，163 / Gmail / Outlook 作为**同一套代码下的配置项**提供（抽取规则与邮箱商无关，只是 IMAP host/端口不同）。Gmail 门槛最高（要先开两步验证），单独引导。

### 4.3 MVP 做 / 不做

**做（给同学的第一版）**
1. **投递进度**：扩展自动记 + 本地 CSV + 看板。核心闭环，零外网。— 原因：这是产品存在的理由。
2. **邮箱通知（`source = imap`）**：向导配置 + 直连自己的 QQ 邮箱 + 本地落 `data/notices.csv`。— 原因：必须新做的唯一部分。
3. **机会库（本地快照）**：随包带 `data/opportunities.json`，`source = off`，只读可筛。— 原因：零改动即可用，不做可惜。
4. **一份能照着做完的安装说明 + 首次启动引导**。— 原因：整条旅程的成败全在这里。**它不是「配套文档」，是乘数项**：RICE 分不高（6.67，因为 Impact 只算「对单个用户的便利」，没算它决定用户能不能用到产品），但它决定前 3 项功能的 Reach 能不能成立——没有它，装不上 = 三项功能对同学全部不可见。因此它按「不做就可能归零」的等级进 MVP，不参与 Backlog 排期。
5. **浏览器扩展（开发者模式加载）**：保持现状。— 原因：上架要成本和时间，先不上。

**不做（进 Backlog）**

| 不做的事 | 原因 |
|----------|------|
| Chrome 应用商店上架扩展 | 要开发者账号和审核周期；先用「开发者模式加载」顶住。**这是《安装说明》里最烦的一步，但放弃成本最高的一步不在这**。若发行后反馈「装扩展太难」，再评估上架。 |
| 打包成 `.exe` / `.app`（PyInstaller 等） | 能直接干掉「装 Python」这个第一大坎，但体积大、杀软误报、作者要多学一套打包流程。**列为下一个版本的头号候选**，不进 v1。 |
| 机会库自动更新 | 要个能公开访问的数据源+定时任务，v1 不搭。快照 + 页顶标注日期即可。 |
| Docker / 云端托管 | 与「数据在各自电脑里」的产品定义冲突，且门槛比装 Python 更高。排除。 |
| 多设备同步 / 账号体系 | 明确违背「本机一套、互不可见」。排除。 |
| Windows 一键开机自启 | 现有 `开机自启.command` 只有 macOS；Windows 要做「任务计划程序」说明，v1 先只保证「双击能用」，自启进 Backlog。 |
| 邮箱支持 Gmail/Outlook 的开箱即用 | v1 的抽取与链路先跑通 QQ；其余作为配置项提供，不写进默认引导。 |

### 4.4 功能优先级（RICE）

| 功能 | Reach | Impact | Conf. | Effort | Score | MVP? |
|------|-------|--------|-------|--------|-------|------|
| 投递进度闭环（扩展+CSV+看板） | 10 | 3 | 100% | 1（已有） | 30.0 | 是 |

### 5.2 同类工具怎么解决「邮箱通知自动识别」这一步

三条主流路线：

1. **Gmail/Outlook OAuth 只读扫描**（Prowl、Applendium、G-Track、Job Application Tracker）——**主流做法**。优点：一键授权、实时。代价：必须依赖 Google/Microsoft 账号体系，国内 QQ/163 用户用不上；隐私上要把邮箱交给工具（有评测作者明确表态「不喜欢 tracker 连我的 Gmail」）。
2. **IMAP + 授权码，本地脚本**（`mailpilot` 这类开源项目、以及本项目的 `qqmail2table`）——**离我们最近**。优点：数据不出本机、QQ/163/Gmail 统一走 IMAP。代价：要用户自己开会话、拿授权码、填配置。
3. **浏览器扩展抓投递页**（Simplify autofill、本项目的「投递成功」识别）——从**投递端**记，不碰邮箱。优点：不用交邮箱。代价：站点改文案就漏（本项目为此加了「记一笔」兜底）。

**用户抱怨排名（跨工具共性）**：① 初始设置就卡死（尤其「连不上 Gmail/403」）；② 隐私——不愿把邮箱交给第三方；③ 手动维护跟不上，三周断更；④ 识别不准（邮件模板千奇百怪）；⑤ 免费版有额度墙。

**对我们的启示**：本项目天然占住 ①②④ 的位置（本地、不交邮箱、有兜底）。**唯一的软肋正是 ①——初始设置**，也就是这份 PRD 第 3 节和第 4.3 节死磕的地方。

### 5.3 非开发者分发本地小工具的通行做法与门槛

| 做法 | 门槛（对「没装过 Python 的同学」） | 说明 |
|------|-----------------------------------|------|
| **压缩包 + 双击脚本**（本项目现状） | 中：要装 Python、要会解压到固定目录、macOS 首次双击要被拦 | 零基础设施成本，最灵活；门槛集中在 Python |
| **打包成安装包**（PyInstaller / py2app 出 `.exe`/`.app`） | 低：双击就装，不用管 Python | **能干掉第一大坎**；代价是作者要维护打包流程、体积几十 MB、Windows 杀软可能误报 |
| **Docker** | 高：要先装 Docker Desktop，本身比装 Python 更重 | 对目标用户是负优化，排除 |
| **云端托管**（Vercel/Render/PikaPods 等） | 低（给链接就能用），但**要有人出服务器和运维**，且与「数据在本地」冲突 | 与我们产品定义矛盾 |
| **pipx / npm 全局安装** | 中高：要有包管理器，非开发者更陌生 | 只适合会 Python 的用户 |
| **Chrome 应用商店上架扩展** | 低（点安装即可），但有 $5 开发者费 + 审核周期 | 能免掉「开发者模式加载」，是**第 5 步的门槛**的解药 |

业界经验：对「一次性、个人用、要本地数据」的工具，**「打包成安装包」是公认最低门槛且不牺牲隐私的路**（代价在作者侧）；「压缩包 + 脚本」是成本最低、能先跑起来的路。**v1 建议先用压缩包跑通闭环，把「打包成安装包」列为下一个版本的第一优先级**——因为装 Python 是目标用户的第一大放弃点。

### 5.4 各家邮箱开 IMAP 拿授权码的难度对比（决定方案可行性）

| 邮箱 | 要先开什么 | 拿「授权码」步骤 | 额外坑 | 难度 |
|------|------------|------------------|--------|------|
| **QQ 邮箱** | IMAP/SMTP 服务 | 网页登录 → 设置 → 账号与安全/账户 → 开启服务 → 手机发短信验证 → 弹 **16 位授权码** | 授权码**只显示一次**；填错成 QQ 密码会一直失败 | **低**（默认方案） |
| **163 / 126** | IMAP/SMTP 服务 | 设置 → POP3/SMTP/IMAP → 开启 → 生成「**客户端授权密码**」 | 名词叫「授权密码」不是「授权码」，同学易困惑 | 低–中 |
| **Gmail** | **先开两步验证** | Google 账户 → 安全性 → 两步验证 → 生成「应用专用密码」（16 位） | 必须先具备两步验证；需能正常访问 Google 服务 | **中**（门槛最高） |
| **Outlook / Microsoft 365** | 两步验证（或走 OAuth） | account.microsoft.com → 安全 → 应用密码 → 新建 | 企业域场景更绕；有 OAuth 正路 | 中 |

**结论**：**QQ 邮箱是唯一「低难度且覆盖大多数国内同学」的选择**，作为 v1 默认合理。163 紧随其后（只是名词不同，引导里点明即可）。Gmail/Outlook 门槛明显更高，不进默认引导。

## 6. 关键风险（以「一个没装过 Python 的同学」为视角，按严重程度排序）

1. **【P0·最可能直接放弃】装 Python 3.9+。**
   表现：不知道要装；Windows 忘勾 Add to PATH → 双击全闪退，同学以为是程序坏了；装完不知道怎么验证。
   影响：卡在这一步 = 产品对他完全不可用。
   缓解：下载页大字提示「勾 PATH」；`start.bat` 检测不到 Python 时打中文提示并停住；引导页第一屏做环境检测。**长期解药 = 打包成 exe/app（Backlog 第一位）。**

2. **【P0·最可能配不下去】走完「开 IMAP → 拿授权码 → 填对」。**
   表现：找不到设置入口；把登录密码当授权码填，反复登录失败；授权码只显示一次没存；Gmail 还多一步两步验证。
   影响：邮箱通知这一栏空着，产品价值砍掉三分之一。
   缓解：分邮箱图文引导 + 程序内向导「当场试登录并说明失败原因」；**允许跳过**，跳过时页面给出「怎么回来配」，不报错不卡死。

3. **【P1·烦但会硬着头皮做】以开发者模式加载扩展。**
   表现：找不到「开发者模式」开关；选目录时选错到上一层，报「清单文件缺失」；Chrome 更新后扩展被停用；改过端口后扩展连不上服务。
   影响：自动记投递这个核心卖点失效，退化成纯手抄（但看板还能用）。
   缓解：逐屏截图 + 高亮；明确「选 `extension` 文件夹本身」；扩展连不上时自动发现并提示当前服务端口，不让用户去改代码。**长期解药 = 上架应用商店（Backlog）。**

> 补充观察（第 4 名，够不上「放弃点」但会反复出现）：**服务没起就打开了看板**（页面白/报错）、或 **8788 端口被占**。靠 start 脚本自动换端口 + 引导页写「那个黑窗口不要关」可缓解。

### 数据埋点（精简）

发行版本机运行，**不做联网埋点**（与隐私承诺冲突）。只在本地留**可选的**最小使用日志，默认关闭、绝不上报：

- 首次启动是否跑通（环境检测结果：Python 版本、是否成功起服务）——用于引导页自查，写本地日志文件；
- 邮箱授权是否成功（是/否 + 失败原因分类），**不记邮箱地址、不记授权码**；
- 若将来要上架应用商店/做公开下载页，再在**下载页**侧做获客埋点（page_view / download_click）。
