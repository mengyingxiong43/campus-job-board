# ADR-003：发行包用 git archive 构建，并对私有数据做入库前扫描

## Status
Accepted（2026-10-07）

## Background
要把作者自用的一套发给同学，**`data/` 一个字节都不能进包** —— 否则等于把作者 165 条真实投递记录、
9381 条机会库、飞书 token 一起发出去。现状：`.gitignore` 已忽略 `config.ini` 与 `data/*.csv|*.json|*.html`，
且实测 `git ls-files data/` 为空（data 未被跟踪）。但仍需一个**可重复、有校验**的打包流程，
防止「手工拷文件夹」把未跟踪的 `data/` 带进去（历史踩坑：README 记录过两次真实公司名进了演示截图）。

## Decision
**锁定：`git archive` 从已提交的 tag 导出 + 打包后扫描泄漏。** 打包脚本 `tools/make-release.py`。

### 为什么是 git archive
| 方式 | 会不会带上 data/ | 可复现 | 判断 |
|------|------------------|--------|------|
| **git archive <tag>** | **不会**（只含已跟踪文件，data/ 未跟踪） | 是（tag 即快照） | **采用** |
| 手工拷目录 / zip 整个文件夹 | **会**（连 config.ini、data/ 一起） | 否 | 排除 |
| PyInstaller / py2app | n/a（产品形态变更） | 是 | Backlog 头号候选（PRD 4.3），不进 v1 |

### 打包脚本 `tools/make-release.py` 的步骤（每步失败即中止、不产出）
1. **前置门禁**：`git status --porcelain` 必须为空（被打包的 = 被测试的）；`python3 applytracker.py --self-test` 全绿；`node tools/board-check.js` 全绿。
2. **导出**：`git archive --format=zip --prefix=applytracker-{ver}/ <tag> -o dist/applytracker-{ver}.zip`。
   单层目录（`--prefix` 只套一层），对应 PRD 旅程第 0 步「不许双层目录」。
3. **扫描泄漏（关键一步）**：解压到临时目录后逐项断言——
   - **禁止路径**：存在任何 `data/**` 或 `**/config.ini`（非 `config.example.ini`）→ 中止；
   - **禁止内容**：拿**当前工作树**的真实值当词表（不把秘密写死进扫描脚本，否则扫描脚本本身进包又成泄漏源）：
     读本机 `config.ini` 里所有 `feishu_base_token/table_id/app_secret` 值、
     读 `data/applications.csv` 里所有 `公司名称`、`samples/` 之外的公司名，
     在包内所有文本文件中搜索这些字面量，命中任一 → 中止；
   - **授权码扫描**：正则扫 `[mail] authcode` 形态的 16 位串。
4. **入包清单核对**：`.gitignore` 里列出的忽略项（`config.ini`、`data/*`）在包内**必须为零**。
5. 通过后才把 zip 移到 `dist/`。

> 扫描脚本读当前工作树的真实 secret 做词表，是为了让**校验本身不需要持有任何秘密**——脚本进包也无害。

### 随包分发的数据（这是「允许进包」的白名单，与 `data/` 严格区分）
- `samples/`：**投递记录与邮箱通知全是虚构演示数据**（`投递记录样例.csv`、`看板样例.html`、截图），由 `tools/make-demo-data.py` 固定种子生成，作者已核实无真实企业名。**允许进包**。
  - **2026-10-13 修正**：`samples/shot-opps.png`（README 里机会库那张图）改用**随包公开快照**（`snapshot/opportunities.json`）的真实规模拍摄 ——
    那张图要证的就是「首次启动即自带九千多条岗位」，拿 60 条虚构数据拍出来会让人以为这个功能是空的。
    该快照本身就是下面这条「允许随包分发的公开数据」，与使用者私有 `data/` 无关；图上只显示岗位总数与行业 / 批次 /
    企业性质等统计口径，**不出现任何公司名**。
  - 因此「`samples/` 全是虚构数据」这句**不再逐文件成立**，取而代之的判据是：
    **投递记录页与邮箱通知页上的公司名必须全部来自演示名单** —— `tools/make-screenshots.js` 出图前强制校验
    （`DEMO_DIR` 指向演示目录、读它的 CSV 当名单），只要有一家不在名单里就中止、一个文件都不写。
    这条判据覆盖了真正会泄漏的东西（作者的投递记录、邮箱通知），比原先那句更准。
- `data/opportunities.json`（约 6.5 MB，公开的招聘汇总信息）：按 PRD 4.1，作为**本地快照**随包带。
  但它当前在 `data/` 下且被 `.gitignore` 忽略 → **不能靠 `git archive` 带出**。
  做法：改为把这份快照放在被跟踪的 `snapshot/opportunities.json`（新目录，明确「非私有」），
  首次启动时拷贝进 `data/`（见 ARCH 第 4 节）。这样既进得了包、又与用户私有 `data/` 隔离。

## Consequences
- 正面：打包过程可复现、有强制校验、失败即中止（对应 README 里「一个文件都不写」的既有纪律）。
- 负面：新增 `tools/make-release.py` 与 `snapshot/` 目录；打包前必须 commit + tag（未提交内容不进包）。
- 风险：若同学拿到包后又在自己机器上跑出真实数据，再转发给别人 —— 不在本方案责任内（`data/` 从未进过包，用户自己的数据由用户自己负责）。
