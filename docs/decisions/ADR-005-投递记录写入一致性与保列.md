# ADR-005：投递记录读写加文件级互斥锁 + 原子写 + 保留用户自定义列

## Status
Accepted（2026-10-07）— 修复已复现的数据丢失

## Background
实测缺陷：`load_apps()` → 改内存 → `_write_all()` 全量覆盖，**全程无锁**。
多线程服务（`ThreadingServer`，`applytracker.py:6834`）下并发即丢写：**实测 10 并发只进 3 条**
（很可能就是作者「投了没记」的成因）。
现状代码路径：
- `load_apps` 读全表（`applytracker.py:203`）；
- `add_app`（283）/`update_app`（310）/`delete_app`（332）/`set_app_parent`（455）各自 load→改→`_write_all`；
- `_write_all`（219）写 `.tmp` 再 `os.replace` —— **原子性已具备**，缺的只是**互斥**；
- `APP_LOCK`（1077）只被飞书同步路径用（1254 非阻塞 acquire / 1297 release），**本地写入完全不碰它**。

附带缺陷：`load_apps` 只取 `CSV_FIELDS` 十列（`applytracker.py:213`），`_write_all` 也只写这十列（223/226）——
用户在 Excel 里手工加的列会被**静默抹掉**（且 `--import-apps` 路径同样，1044）。

## Decision
**锁定三件事一起做。**

### 1. 文件级互斥锁（新增 `APP_FILE_LOCK = threading.RLock()`）
- `APP_FILE_LOCK` **专职保护对 applications.csv 的「读—改—写」临界区**，与 `APP_LOCK`（只表达「飞书同步忙不忙」的状态）职责分离。
- 抽出唯一入口 `mutate_apps(cfg, fn) -> Any`：
  ```
  with APP_FILE_LOCK:            # 阻塞，保证写串行
      rows = load_apps(cfg)
      result = fn(rows)          # 就地改 rows，返回需要的值
      _write_all(cfg, rows)      # 仍是 .tmp + os.replace
      return result
  ```
  `add_app` / `update_app` / `delete_app` / `set_app_parent` / 改名记账 全部改走 `mutate_apps`。
- 飞书同步写入段（1275 附近）也持 `APP_FILE_LOCK` 后再写，保证「同步」与「用户手改」不互相覆盖。
- **避免死锁**：同步路径先持 `APP_LOCK`（busy 标记）再持 `APP_FILE_LOCK`；本地写入只持 `APP_FILE_LOCK`、
  从不反向请求 `APP_LOCK` → 无环。

### 2. 原子写保留（不动）
`_write_all` 的 `.tmp` + `os.replace`（`applytracker.py:221-227`）保留。同一文件系统上 `os.replace` 原子。
锁解决丢写，`.tmp` 解决「写一半崩了」。

### 3. 保留用户自定义列
- `load_apps`：**不再丢列** —— 记录 `reader.fieldnames` 的顺序，把 `CSV_FIELDS` 之外的列原样带进每行 dict。
- `_write_all`：写出列序 = 原始列序（若有）∪ `CSV_FIELDS`（补齐缺失的），**自定义列原位置保留**；
  新行按 `CSV_FIELDS` 顺序写、自定义列留空。
- `--import-apps` 的写盘路径（1044）共用同一个 `_write_all`，一并修好。
- 与前端兼容：`load_apps` 返回的 dict 现含额外键，前端按 `r["列名"]` 取值不受影响（多出的键不读即忽略）。

## Consequences
- 正面：并发写入不再丢（回归：50 并发应进 50 条）；进程崩溃不产生半截 CSV；用户 Excel 加的列不再被吞。
- 负面：所有写变成串行（本机单人场景，可忽略）。
- 回归/自检项：① 50 并发 `add_app` 后行数 = 50；② CSV 手加一列 `内推人` 后跑一次 `update_app`，该列仍在、值不变；
  ③ 现有 6910–6966 的增删改用例全绿（它们直接调 `add_app/update_app/delete_app`，函数签名不变）。
