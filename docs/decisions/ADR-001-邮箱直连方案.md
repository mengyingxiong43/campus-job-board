# ADR-001：用标准库 imaplib 直连用户自己的邮箱

## Status
Accepted（2026-10-07）

## Background
发行版每人本机一套，邮箱通知必须由用户连自己的邮箱（作者原链路借 WorkBuddy 连接器凭据，别人拿不到）。
硬约束：单文件 `applytracker.py`、**零第三方依赖**、Python 3.9 可跑。
现成资产：隔壁 `../qqmail-job-tracker/qqmail2table.py`（1960 行）已经是一套 `imaplib` + 正则的本地抓取器，
产物 `notifications.csv` 与 `applytracker` 的 `[notices] source = file` 格式本就兼容
（列见 `applytracker.py:1342`、`qqmail2table.py:688`）。

## Decision
**锁定标准库 `imaplib.IMAP4_SSL` + `email` + `ssl`**，不引第三方库、不引 OAuth。

三种候选的实测取舍：

| 方案 | 覆盖 QQ/163/学校邮箱 | 满足「定时+增量+正文解析」 | 零依赖 / 3.9 | 判断 |
|------|----------------------|----------------------------|---------------|------|
| **imaplib 标准库** | 是（授权码登录） | 是（见下） | 是 | **采用** |
| OAuth 2.0 / XOAUTH2 | 只对 Gmail/Outlook 必需 | 是，但要多一套浏览器授权 + 令牌刷新 + 注册应用 | 标准库够用但工程量大 | 不进 v1，留 SEAM |
| 第三方 `imapclient` | 是 | 是 | **否**（违反零依赖） | 排除 |

能力逐项核验（对照 `qqmail2table.py` 已在跑的实现，不是纸上推演）：

- **连接/登录**：`imaplib.IMAP4_SSL(host, port, ssl_context=ctx)`（`qqmail2table.py:562`）。
  `timeout` 形参 Python 3.9 起支持，与本项目 3.9 底线一致。
- **增量**：`imap.search(None, f'(SINCE {dd-Mon-yyyy})')` 拉一个时间窗（默认 30 天，`qqmail2table.py:580`），
  再按 `Message-ID` 指纹去重（`dedupe`，`qqmail2table.py:665`）。状态落 `data/.mail_state.json`（`load_state/save_state`，648/658）。
- **不误标已读**：`select(folder, readonly=True)` + `fetch(uid, "(RFC822)")`（576/590）。
- **正文解析**：`email.message_from_bytes` + `extract_body`（multipart 遍历、`Content-Transfer-Encoding` 解码、
  charset 回退、HTML 转文本）见 `qqmail2table.py:251-300`；链接抽取 `extract_links`（301）。

**结论：标准库完全满足，且已有可移植的参考实现，不引第三方库、不引 OAuth。**

### 主流邮箱配置差异（host 做成可配置表）

| 邮箱 | IMAP host / 端口 | 凭据 | 前置开关 | 额外坑 |
|------|------------------|------|----------|--------|
| QQ | `imap.qq.com` : 993 SSL | **16 位授权码** | 设置→账户→开启 IMAP/SMTP | 授权码只弹一次；用密码登不进 |
| 163 / 126 | `imap.163.com` / `imap.126.com` : 993 | 「客户端授权密码」（名词不同） | 设置→POP3/SMTP/IMAP 开启 | 部分账号要求登录后先发 `ID` 命令（`M.xatom("ID", '("name" "applytracker" ...)')`，包 try/except），否则报 `Unsafe Login` |
| Gmail | `imap.gmail.com` : 993 | 「应用专用密码」（16 位） | **先开两步验证** | 不给 2FA 就没有应用密码；正式解法是 OAuth（Backlog） |
| Outlook / M365 | `outlook.office365.com` : 993 | 应用密码或 OAuth | 两步验证 | 多数租户已停用基础认证，实质需 OAuth |
| 学校邮箱 | 视学校（多为 Coremail / 腾讯企业邮 / Office365） | 多为授权码 | 查学校 IT 页 | host 必须用户自填，程序不猜 |

**v1 默认 QQ，其余作为同一套代码下的 `[mail] host/port` 配置项**，UI 给一张 host 预设下拉。

### SEAM（留给 Gmail/Outlook 的正式路）
`_mail_login(imap, cfg)` 抽成一个函数：默认走 `imap.login(user, authcode)`；
未来加 OAuth 时改为 `imap.authenticate("XOAUTH2", lambda x: (user, token))`，不动上层。**v1 不实现**。

## Consequences
- 正面：零新依赖；复用已跑通的 imaplib 代码；QQ/163/学校邮箱开箱可用；数据不出本机。
- 负面：Gmail/Outlook 在 v1 只走「应用密码」降级路径，且 Gmail 应用密码需先开 2FA，门槛高 → 不进默认引导。
- 安全：授权码存 `config.ini` 的 `[mail] authcode`（`config.ini` 已被 `.gitignore`；`run_wizard` 写盘时 `chmod 0o600`，见 `qqmail2table.py:1131`）。
  另支持从环境变量 `APPLYTRACKER_MAIL_AUTHCODE` 读，优先于明文。**授权码不回显、不进日志、打包扫描时按敏感串处理。**
