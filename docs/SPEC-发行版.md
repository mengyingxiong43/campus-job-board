## 0. 目标档（锁定，验收按这一节，不按感觉）

> 用户已裁定「按对外发布档验收」。档位是运维记分卡的七维体系（铜 Bronze / 银 Silver / 金 Gold）。

**目标档 = Silver（对外发布）；总档取各维最低；可观测不适用于本机单机工具。**

三句话都是硬口径，逐条写明理由，免得验收时各执一词：

1. **为什么是 Silver 不是 Gold** —— 记分卡里「对外发布 / 商业级」的最低线就是 Silver，Gold 留给关键系统。我们是对外发给同学用的单机工具，够到 Silver 即可。
2. **为什么总档取最低** —— 木桶效应，不是平均也不是加权。现在七维里最低的是「无障碍」= Bronze，所以**当前总档就是 Bronze**。把无障碍拉到 Silver，总档才跟着变 Silver；把别的维刷再高也没用。
3. **为什么可观测显式声明「不适用」** —— 本机单机工具，没有服务端运维方，SLI/SLO 没有消费者。它**不参与取最低**（否则总档永远卡死），但也不许装作达标。

### 七维现状（运维实测）

| 维度 | 现状 | 一句话 |
|------|------|--------|
| 测试+回归 | Bronze | 自检 476 项 + board-check 132 项都在，但还没进自动门禁（CI 在做） |
| 契约 | Bronze | 缺统一错误模型 `{ok:false, code, msg}` |
| 安全 | **Silver 达标** | Origin 校验、写锁 + 原子写、零第三方依赖、只听 127.0.0.1、打包强制泄漏扫描 |
| 无障碍 | **Bronze 未达（当前唯一最短板）** | 键盘不可达 + 语义标签缺失 |
| 性能 | Bronze | 缺 p95 预算 |
| 可观测 | **不适用（显式声明）** | 本机单机工具，没有服务端运维方 |
| 发布安全 | **Silver 达标** | git tag 发布 + 保留上一版包可回退；数据每日快照留 14 天 |

### 无障碍拆开的三条（判据，改的时候按这个判，别多改）

| 项 | 判定 | 依据 |
|----|------|------|
| 键盘可达 | **不合格** | `tabindex` 全库 0 处、`keydown` 0 处、5 处 click 挂在非按钮元素上 |
| 语义标签 | **不合格** | `aria-*` 全库仅 2 处、`<label>` 0 个、`<th scope>` 0 个（`<th>` 有 30 个） |
| 对比度 | **已达标，不用改** | 8 组主色配对全部 ≥4.5，多数 ≥7（AAA）。**这条写在这里，免得以后有人再来一轮** |

## 1. 产品定义

- **一句话**：把作者自用的秋招投递看板，做成「同学在自己电脑上装一套、数据各在各电脑里」的发行版。
- **目标用户**：正在秋招的同学，大概率没装过 Python。
- **核心问题**：现有版本只在她电脑上跑得通，因为它依赖三样只有她有的东西 —— 她的飞书多维表格、她 WorkBuddy 里的邮箱连接器授权、她手工配置的路径。别人拿不走。

## 3. 明确不做（锁定，开发中如有人提出直接拒绝）

| 不做 | 原因 | 何时考虑 |
|------|------|----------|
| 让同学也装 WorkBuddy / 邮箱连接器来接邮箱 | 用户 2026-10-07 已否决这条路线（代价过高，且需剥离作者隐私配置） | 不打算做 —— 邮箱走**看板自己 IMAP 直连**（已落地，见 §2） |
| 账号体系 / 多租户 / 云端托管 | 形态是「每人本机一套」，数据留在各人电脑里，天然隔离 | 不打算做 |
| 拆多文件工程 / 引第三方依赖 | 「单文件 + 零依赖 + 能整套发给别人」是既定取舍 | 不打算做 |
| v1 打包成 exe/app | 工作量独立且大 | 下一版第一优先级（PRD 已列） |
| Gmail / Outlook 的 OAuth | 需要注册应用与令牌刷新，工程量大 | v1 只走应用密码降级 |
| 机会库自动更新 | 同学没有作者的飞书表，随包快照够用 | 有反馈后 |
| 联网埋点 / 使用统计 | 与「数据留在本地」的承诺冲突 | 不打算做 |
| 上架浏览器扩展商店 | 需要开发者账号与审核 | 有反馈后 |
| 用大模型识别邮件 | 每个人的 key 与费用问题，且不可解释 | 不打算做 |

## 4. 技术架构（锁定）

见 `ARCH-发行版化.md` §0 锁定项表（L1–L10）。要点复述：

- 邮箱：标准库 `imaplib.IMAP4_SSL` + `email` + `ssl`，授权码登录，**内联进 `applytracker.py` 新章节**（不拆模块、不引子进程）。
- 识别：纯规则引擎，移植 `../qqmail-job-tracker/qqmail2table.py` 的纯函数，**不调大模型**。
- 信任边界：关掉通配 CORS，改 `_origin_ok()` 校验。
- 写入：`APP_FILE_LOCK`（RLock）+ `mutate_apps(cfg, fn)` + 原子写 + 保留自定义列。
- 备份：启动时按日快照 `data/backups/`，留 14 天。
- 打包：`git archive <tag>` + 打包后私有数据扫描（命中即中止）。

**新增运行时文件**（均在 `data/`，不进包）

- `mail_skipped.jsonl`（明确不记录的：宣讲会/拒信/订阅等）
- `notice_evidence.json`（命中依据旁路，不改 `notices.csv` 列）
- `backups/`（每日快照）

**新增被跟踪文件**
- `snapshot/opportunities.json` —— 随包快照。**首启预置已落地（v0.33.0，commit 34be4a3）**：
  `load_opportunities()`（serve 启动、首屏 `/api/board`、`--report` 导出、公司补全共用的唯一装载入口）顶部
  挂了 `seed_opportunities_snapshot()`：`data/opportunities.json` 不存在且快照存在时按字节原子拷入 `data/`，
  并打印「机会库首次预置完成：N 条公开岗位（来自随包快照）」（N 从快照 JSON 数出）。
  快照路径按脚本所在目录解析（不依赖 cwd）；**绝不覆盖**已存在的 `data/opportunities.json`；
  快照缺失/损坏 → 静默跳过。见 AC-09。

**不改动**
- `applications.csv` 的列与语义
- `notices.csv` 的列（`NOTICE_FIELDS`）
- 已定型的界面结构

## 6. 界面变更（最小化）

- 邮箱通知页：未配置邮箱时显示一条「怎么配」的提示，不报错、可跳过。
- 邮箱通知页：有未匹配邮件时显示「N 封没认出公司」提示条，点开可一键归类（写 `mail_aliases.json`）。
  —— 这一条只管**公司认不出**那类（v0.31.0 起「类型认不出」不再走旁落，见 AC-12b）。
- 邮箱通知页：类型认不出的行**照样在通知表里**，类型那一格显示成可点的下拉，角标写「待确认」，
  点一下选类型即写回；**单类型行也能改**（选错不是单向门）。
- 其余页面不动。

## 7. 验收标准（EARS）

| 编号 | 功能 | 验收标准 | 优先级 |
|------|------|----------|--------|
| AC-01 | 加固·CORS | If 请求带 `Origin: https://evil.com`，系统**必须**返回 403（GET/POST/OPTIONS 一致） | P0 |
| AC-02 | 加固·CORS | While 请求无 Origin，或 Origin 为 `chrome-extension://` / `http://127.0.0.1:<port>`，系统**必须**放行 | P0 |
| AC-03 | 加固·写入 | When 50 个并发写入同时发生，系统**必须**保证 CSV 行数增加 50（不丢） | P0 |
| AC-04 | 加固·保列 | When 用户在 CSV 手工加了一列并触发一次更新，系统**必须**保留该列与列序 | P0 |
| AC-05 | 加固·备份 | While 服务启动，系统**必须**在 `data/backups/` 生成当日快照；备份失败**不得**阻断启动 | P0 |
| AC-06 | 加固·父链 | While 公司归并链达到 20 层，系统**必须**正确上溯到根（不冒到顶层） | P0 |
| AC-07 | 首启·独立运行 | While 同学机器上未配任何飞书与邮箱，系统**必须**能正常启动且看板可用 | P0 |
| AC-08 | 首启·配置生成 | When 首次启动且 `config.ini` 不存在，系统**必须**自动生成并设权限 600 | P0 |
| AC-09 | 首启·快照 | When 首次启动且 `data/opportunities.json` 不存在，系统**必须**从 `snapshot/` 拷入 | P0 **已落地** v0.33.0（`seed_opportunities_snapshot()` 钩在 `load_opportunities()` 唯一共用装载入口；原子拷入、绝不覆盖已有文件、快照缺失静默跳过；成功打印预置行，N 从快照数出。见 §5） |
| AC-10 | 邮箱·识别 | When 抓到一封明确的校招通知，系统**必须**标出正确的类型与公司 | P0 |
| AC-11 | 邮箱·同分决胜 | If 一封邮件同时命中多类且分数并列，系统**必须**按类型优先级取胜（`资料补充 > AI面 > 笔试 > 测评 > 面试`），并**必须在识别依据里写明**「同分、按优先级取了哪个」——**不许静默决胜**，静默决胜就跟整个功能「可解释」的底线冲突 | P0（v0.32.0 修的退化：并列判定曾只看分数、丢了优先级那一维，加了裸「测评」之后反而把「笔试测评通知」认成了空） |
| AC-12 | 邮箱·公司认不出 | If 邮件里的公司名对不上用户名单，系统**必须**进未匹配区（`mail_unmatched.csv`）且**不出现在任何公司的通知里** —— 这一类是**唯一**走旁落的 | P0 |
| AC-12b | 邮箱·类型认不出（用户 2026-10-08 裁定） | If 公司认得出、但类型认不出，系统**必须照样进通知表**（不进旁落 CSV，用户不会想到去开一个 CSV 看），类型**留空** —— 数据层用**空串**，**不许**把「待确认」三个字写进数据；「待确认」只是前端渲染角标时加的 | P0（v0.31.0 落地） |
| AC-12c | 邮箱·类型可改 | When 用户在通知表上给一行选了类型（含单类型行改类型），系统**必须**写回 `notices.csv`，且**必须**把该行已挂的处理状态与识别依据迁到新键上（`notice_state_key` 含类型，改类型会变键，**不许**让用户的手工标记静默丢失） | P0（v0.31.0 落地） |
| AC-13 | 邮箱·归类 | When 用户对一封未匹配邮件指定公司，系统**必须**写入 `mail_aliases.json`，下次同域自动命中 | P1 |
| AC-14 | 打包·防泄漏 | When 打出发布包，扫描**必须**确认包内无 `data/**`、无 `config.ini`、无作者真实 token/公司名，命中即中止 | P0 |
| AC-15 | 扩展·端口 | While 服务运行在非 8788 端口，扩展**必须**自动探测到并正常工作（无需用户改代码） | P1 |
| AC-16 | 启动·人话提示 | If 环境不满足（无 Python / 版本低 / 端口占用 / 目录不可写），系统**必须**用中文说明原因且**不闪退** | P0 |
| AC-17 | 无障碍·键盘可达（A1） | While 用户只用键盘操作，行内**每一个**可点操作**必须**能 Tab 到并回车触发 —— 判据是「可点操作本身是原生 `<button>`」，**不是**给几百行都贴 `tabindex=0`（那会让键盘用户按几百次 Tab 才到底部）；只有**整行可点且行内没有对应按钮**时才给 `tabindex=0` + `role="button"` + Enter/Space | P1（当前最短板，做） |
| AC-18 | 无障碍·键盘不劫持（A1） | While 焦点在输入框 / `<select>` / 按钮里，全局键盘监听**必须**不劫持 Enter（判 `e.target`） | P1（做） |
| AC-19 | 无障碍·语义标签（A3） | When 界面上有自绘下拉 / 自绘开关，系统**必须**改用原生 `<select>` / `<input>`（读屏能识别、键盘能选）；表格表头**必须**带 `scope` | P1（做） |
| AC-20 | 无障碍·对比度 | 8 组主色配对**必须**全部 ≥4.5（多数 ≥7） | P1 **已达标，不用改**（写在这里免得以后有人再来一轮） |

## 8. 边界与约束

- 全程不需要用户打开命令行或输入命令。
- 响应式：投递进度表在 1080px 宽窗口下不横向溢出（作者窗口实测 1050px = 容器宽度，零余量）。
- 性能：机会库 9381 条，接口分页返回；单次 `/api/board` 响应保持现有量级。
- 兼容：Python 3.9+；macOS 与 Windows 都要能跑。

## 9. 内嵌已知坑（从项目记忆拉取）

| 坑 | 位置/指纹 | 根因 | 修法 |
|----|-----------|------|------|
| 改父链上限必打红自检 | `applytracker.py:8176-8178` | 自检硬断言字面量 `"for(let i = 0; i < 6; i++)"` | 改上限时同步改断言与用例名 |
